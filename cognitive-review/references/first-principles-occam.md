# 第一性原理 + 奥卡姆剃刀

审查"想得对不对"的第一层：核心问题是否成立，以及是否有多余。

## 目录
- 第一性原理审查
- 奥卡姆剃刀审查
- 追问话术模板

## 第一性原理审查

不接受"惯例如此""大家都这么做""行业标准"作为理由。回到问题本身逐条追问：

- **要解决的到底是什么问题？** 现在描述的是问题本身，还是某个解法/现象？（常见错误：把"想要一个 App"当问题，真问题其实是"信息找不到"）
- **这个问题真实存在吗？** 有证据吗，还是假想的？多少人真的有？
- **拆到不能再拆的事实是什么？** 去掉所有类比和经验，只剩哪些一定成立的东西？
- **从零开始会怎么设计？** 如果没有任何现有方案的包袱，最直接的路径是什么？现在这套和它差多远？
- **为什么是现在、是这个方式？** 有没有把"路径依赖"误当成"最优解"？

**输出判断**：核心问题是否被正确界定。若发现"解错了问题"或"问题不成立"，直接标**致命**——后面审得再细也是白审。

## 奥卡姆剃刀审查

"如无必要，勿增实体。"逐项问"删掉它会怎样"：

- **哪些功能/章节/字段是多余的？** 删掉后核心目标是否照样成立？成立就该删。
- **有没有为一次性逻辑搭抽象层？** 为"以后可能用到"预留的灵活性/可配置性，当下用不上就是负担。
- **有没有为不会发生的场景做处理？** 防的是真实风险还是想象的风险？
- **论证里有没有重复、绕路、可合并的部分？** 三句能说清的用了三段？
- **最小可用版本是什么？** 砍到只剩"不砍就不成立"的部分，剩下的都是候选删除项。

**判断标准**：每一处保留都要能回答"为什么它必须在"。答不上来 → 标为可删（较大或轻微，看占比）。

## 追问话术模板

- "这一段/这个功能，删掉之后你的核心目标还成立吗？如果成立，为什么留着？"
- "你说要解决 X，但方案在做 Y。X 才是真问题，还是 Y 背后另有目的？"
- "如果这是你从零开始做的第一版，你还会加这部分吗？"
- "支撑这个结论的最底层事实是什么？把类比和'一般来说'都去掉。"
