# AI 产品经理能力地图

## 画像门槛

- **实习/0-1年：** 能基于真实项目拆链路、写清动作与基本证据，不要求负责人所有权。
- **1-3年：** 指满 1 年但未满 3 年；能独立负责模块，从需求判断推进到上线、评测和迭代。
- **3-8年：** 满 3 年即进入本档；能负责产品或产品线，在业务、技术、风险、成本与组织之间做取舍。
- **P7+：** 不只按年限判定；能制定战略和机制，对产品组合、组织协同、商业结果及重大风险负责。

## 业务洞察与场景定义

**定义：** 从真实用户、业务流程和约束出发，找到值得用 AI 解决的问题。

1. **用户与工作流调研**
   - 实习/0-1年：画出用户、任务、输入输出和痛点，并说出实际调研动作。
   - 1-3年：用访谈或数据定位流程断点、影响范围与验证结果。
   - 3-8年：处理多角色和多组织流程，区分提出者、使用者与决策者。
   - 判据：必须出现具体对象、流程节点、证据和结论。
2. **AI 场景价值与真伪需求**
   - 实习/0-1年：比较 AI 与规则方案，指出一项增量和一项风险。
   - 1-3年：从频率、价值、数据、可行性和不确定性成本做取舍。
   - 3-8年：以试点证据终止伪需求或扩大有效场景。
   - 判据：必须解释为什么用或不用 AI，并给出比较依据。
3. **场景拆解与需求抽象**
   - 实习/0-1年：把模糊诉求拆成任务、输入、处理、输出与人工节点。
   - 1-3年：转成能力模块、规则、数据与验收条件。
   - 3-8年：跨客户抽象对象、状态、边界和异常，沉淀复用方案。
   - 判据：拆解结果必须能直接支持产品设计。

## 产品战略与路线规划

**定义：** 把业务目标、市场变化和模型能力转成定位、路线与优先级。

1. **目标、指标与 MVP 范围**
   - 实习/0-1年：给出业务目标、结果指标和首版不做项。
   - 1-3年：基于基线与资源确定 MVP、目标值来源和退出条件。
   - 3-8年：定义产品线级指标树与投资边界。
   - 判据：目标、指标、范围和依据必须相互对应。
2. **路线图与规模化节奏**
   - 实习/0-1年：拆出验证、上线、迭代阶段及交付物。
   - 1-3年：定义里程碑、进入条件、风险与扩展动作。
   - 3-8年：规划 0→1、1→10、10→100 的能力、组织和商业节奏。
   - 判据：每个阶段必须有证据门槛和取舍。
3. **行业、竞品与组织判断**
   - 实习/0-1年：拆解两个 AI 产品的用户、链路与差异。
   - 1-3年：用市场、模型、用户数据和竞品动作形成判断。
   - 3-8年：判断技术与商业周期、竞争壁垒和组织投入是否匹配。
   - 判据：观点必须有产品证据和反证。

## AI技术选型与架构

**定义：** 围绕业务约束选择模型与应用架构，并说清能力边界。

1. **模型、RAG、微调与 Build/Buy 取舍**
   - 实习/0-1年：说明选择某模型或 RAG 的至少两个约束。
   - 1-3年：用效果、数据、时延、隐私、成本和维护做对比实验。
   - 3-8年：设计多模型与自建/采购组合、迁移条件和供应商策略。
   - 判据：必须有备选方案、约束、实验与结论。
2. **Agent、Workflow 与 Tool Calling 设计**
   - 实习/0-1年：画出意图、任务、工具、输出与人工确认链路。
   - 1-3年：定义路由、记忆、参数、重试、异常与回传。
   - 3-8年：设计多 Agent 或平台编排，处理权限、观测、复用和扩展。
   - 判据：每个节点必须对应业务任务和责任。
3. **技术边界与混合架构**
   - 实习/0-1年：指出模型不应承担的刚性任务及兜底方式。
   - 1-3年：组合模型、RAG、规则、GUI、沙箱与人工复核。
   - 3-8年：按风险与指标决定收权、放权或替换技术。
   - 判据：必须明确 AI 做什么、不得做什么。

## 数据与知识工程

**定义：** 把原始材料变成可治理、可检索、可更新、可追溯的 AI 产品资产。

1. **数据获取、清洗与标注**
   - 实习/0-1年：列出数据来源、字段、缺失处理和标注规则。
   - 1-3年：定义采集、清洗、标注、抽检和口径确认流程。
   - 3-8年：规划跨系统供给、责任人、质量门槛与合规边界。
   - 判据：数据规则必须可执行、可抽检。
2. **知识库与检索链路**
   - 实习/0-1年：解释 Chunking、Embedding、检索和 Rerank 的作用。
   - 1-3年：按文档和查询类型设计切片、Metadata、混合检索、重排与引用。
   - 3-8年：规划多知识域、权限、性能和复用能力。
   - 判据：每个技术动作必须对应一个检索问题和失败样本。
3. **更新、冲突与权限治理**
   - 实习/0-1年：说明新知识入库、审核和旧版本处理。
   - 1-3年：设计权威源、版本、生效时间、冲突、权限与修复流程。
   - 3-8年：建立企业级知识资产治理与跨部门责任机制。
   - 判据：更新、冲突、权限和回退均有明确规则。

## 评测与Bad Case闭环

**定义：** 用离线评测、线上指标和错误归因证明产品有效并驱动迭代。

1. **目标分层与评测集设计**
   - 实习/0-1年：区分业务与模型指标，给出样本和通过线。
   - 1-3年：建立业务、任务、模型/RAG 指标，定义基线、标注和验收。
   - 3-8年：设计离线评测与线上监控联动，处理指标冲突并决定发布。
   - 判据：指标必须有口径、样本和决策用途。
2. **Bad Case 分类与根因定位**
   - 实习/0-1年：复述失败样本并判断数据、检索或生成层。
   - 1-3年：按证据定位到数据、检索、Prompt、工具或流程并回归验证。
   - 3-8年：从跨版本错误分布识别系统瓶颈并调整投入。
   - 判据：失败、归因、修复和回归必须闭环。
3. **线上反馈与持续迭代**
   - 实习/0-1年：设计反馈入口并说明如何进入迭代。
   - 1-3年：结合日志、漏斗、显隐性反馈、抽检和实验排优先级。
   - 3-8年：建立跨版本质量看板和 LLM as Judge 校准机制。
   - 判据：反馈必须追到具体改动和再评测。

## 安全合规与可靠性

**定义：** 识别 AI 失控后果，并用控制、降级和审计把风险压到可接受范围。

1. **风险识别与分级**
   - 实习/0-1年：列出幻觉、隐私、越权或偏见风险及后果。
   - 1-3年：按影响、概率和可逆性定义阻断、告警或接受条件。
   - 3-8年：建立业务线风险分类、责任和重大例外机制。
   - 判据：风险必须对应具体场景、后果和负责人。
2. **权限、校验与 Human-in-the-loop**
   - 实习/0-1年：指出高风险动作的人工确认和校验点。
   - 1-3年：设计最小权限、Schema 校验、沙箱、证据引用和人工审批。
   - 3-8年：按业务风险划定自动化授权等级并审查例外。
   - 判据：控制点必须位于执行链路且真正能阻断。
3. **降级、监控与审计**
   - 实习/0-1年：说明模型或 API 失败时的提示和人工接管。
   - 1-3年：定义超时、低置信度与异常输出的重试、降级、日志和告警。
   - 3-8年：制定 SLA、容灾、审计和事故复盘机制。
   - 判据：触发条件、替代路径和记录必须可演练。

## 商业化与成本ROI

**定义：** 把成本与定价、收入、效率和风险收益放在一张账上决策。

1. **商业模式与定价**
   - 实习/0-1年：说出目标客户、付费对象与计费方式的价值依据。
   - 1-3年：比较订阅、按量、席位、抽成或混合计费。
   - 3-8年：设计产品组合、分层权益和规模化收入模型。
   - 判据：价格必须连接客户价值、成本和使用量。
2. **成本模型与架构降本**
   - 实习/0-1年：按调用量、Token 和单价估算模型成本。
   - 1-3年：加入算力、存储、人工、交付和运维计算 TCO，并比较降本方案。
   - 3-8年：建立产品线成本看板和预算阈值，控制边际成本。
   - 判据：成本项、口径和降本影响必须可复算。
3. **ROI 与规模化决策**
   - 实习/0-1年：用一个效率或收入指标说明价值并标明基线。
   - 1-3年：量化收入、工时、风险损失和投入，给出继续或停止条件。
   - 3-8年：把 ROI、CAC/LTV、机会成本和战略价值纳入投资决策。
   - 判据：收益与成本口径必须可核对并影响决策。

## 项目交付与跨团队协作

**定义：** 把产品判断转成算法、工程、设计、运营与业务共同完成的上线结果。

1. **跨职能协作与技术沟通**
   - 实习/0-1年：把需求写成研发可执行的输入、输出和验收条件。
   - 1-3年：借实验与样本协调算法、数据、工程、设计和业务分歧。
   - 3-8年：在多团队冲突中建立共同指标、决策和升级机制。
   - 判据：必须说出分歧、证据、决策和结果。
2. **范围、资源与风险管理**
   - 实习/0-1年：列出里程碑、负责人、依赖和主要风险。
   - 1-3年：处理范围蔓延、资源不足和延期，并用低成本验证减少争议。
   - 3-8年：管理项目组合、关键依赖和资源取舍。
   - 判据：取舍必须有目标、影响和后续安排。
3. **上线验收与持续交付**
   - 实习/0-1年：参与评审、测试和验收并记录上线问题。
   - 1-3年：组织联调、测试、灰度、验收、监控和复盘。
   - 3-8年：建立跨产品发布与质量机制，平衡速度、承诺和技术债。
   - 判据：上线前后均有证据门槛和负责人。

## P7+ 差异要求

| 一级维度 | 相对 3-8 年新增要求 |
|---|---|
| 业务洞察与场景定义 | 决定组织重点服务哪些用户、行业和工作流，并能证明机会筛选结果。 |
| 产品战略与路线规划 | 制定产品组合战略和年度投资节奏，基于外部变化重配资源。 |
| AI技术选型与架构 | 确定平台级技术原则、供应商策略、迁移条件与长期演进边界。 |
| 数据与知识工程 | 建立跨部门数据与知识资产治理、权属和质量责任。 |
| 评测与Bad Case闭环 | 建设公司级 AI 质量体系，以统一证据支持发布和投资决策。 |
| 安全合规与可靠性 | 建立风险偏好、授权等级、事故责任和重大例外决策机制。 |
| 商业化与成本ROI | 对产品组合收入、毛利、现金投入和规模化路径负责。 |
| 项目交付与跨团队协作 | 设计多团队协作机制，解决战略客户、资源和组织冲突。 |
