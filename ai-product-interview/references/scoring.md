# 面试评分与追问规则

## 证据原则

1. 只根据候选人说出的事实、数字、样本、决策和结果评分。
2. 区分真实上线数据、试点/内测数据、测试集数据和目标测算；口径不明先追问。
3. “未考”与“不合格”分开；没有证据不得自动按及格。
4. 假设题只评价推理过程，不替代真实项目所有权。
5. 任一结论必须能追到问题、候选人回答和目标 JD 要求。
6. “表达不完整”不自动等于“能力不合格”；先判断是没有问到、缺少证据、明确错误还是确实没有经验。
7. 没有候选人回答、面试笔记或录音转写时，只能生成招聘假设和判断信号，不得给推进或录用结论。

## 五类证据状态

复盘模式的每项招聘假设必须使用以下一项，不得自行改写为模糊的“待观察”：

| 证据状态 | 使用条件 | 能否形成负面结论 |
| --- | --- | --- |
| 未问到 | 本轮没有提出相关问题，或记录缺失 | 不能，只能转入下一轮 |
| 问到但缺证据 | 候选人有表态，但没有行为、产物、数字、样本或结果支撑 | 可以形成风险，但不能写成已证实不会 |
| 回答明确错误 | 回答与可核验事实、机制或简历内容直接冲突，且追问后未纠正 | 可以，必须引用具体回答和岗位影响 |
| 候选人承认无经验 | 候选人明确说明没有做过；假设题只能补充判断思路 | 可以形成经验缺口，不能伪装成项目证据 |
| 证据充分 | 候选人给出具体行为、产物、数据、取舍和结果，且与简历和 JD 一致 | 可以支持通过该项门槛 |

## 八维三档评分

| 一级维度 | 好 | 及格 | 不合格 |
|---|---|---|---|
| 业务洞察与场景定义 | 说出具体用户、流程断点、基线证据，并解释为何用或不用 AI。 | 讲清真实场景及基本拆解，但证据量或反证不足。 | 只讲功能愿景、用户有痛点或行业趋势，无法落到真实流程。 |
| 产品战略与路线规划 | 说出目标值来源、MVP 不做项、阶段门槛和路线调整依据。 | 给出目标、优先级和阶段计划，但里程碑缺少证据门槛。 | 把功能排期当路线图，无法说明目标、取舍或退出条件。 |
| AI技术选型与架构 | 比较多条路线，用效果、成本、时延、隐私等证据说明取舍和边界。 | 解释现有架构与主要节点，但实验对照或失败路径不完整。 | 只报模型、RAG、Agent 等名词，无法说明为什么这样设计。 |
| 数据与知识工程 | 说出数据口径、切片/检索依据、质量规则、更新冲突和权限方案。 | 描述数据处理与知识库主链路，但治理和长期维护较弱。 | 只说有知识库或高质量数据，无法提供结构、规则与样本。 |
| 评测与Bad Case闭环 | 给出基线、评测集、指标口径、失败样本、归因修复和回归结果。 | 有指标与 Bad Case 流程，但样本设计或修复验证不完整。 | 只报准确率，或把失败统一归因于模型能力。 |
| 安全合规与可靠性 | 说出具体风险后果、分级、阻断点、降级路径和审计证据。 | 识别主要风险并设置人工复核，但权限、监控或演练不足。 | 只说注意合规，或让模型承担不可逆的高风险动作。 |
| 商业化与成本ROI | 能复算成本和收益，解释定价、单位经济性及预算变化下的取舍。 | 说出一类收益与主要成本，但口径或规模化条件不完整。 | 只讲降本增效、体验提升或换便宜模型，没有可核对的账。 |
| 项目交付与跨团队协作 | 说出分歧、证据、决策、责任、上线门槛和最终结果。 | 描述计划、协作与交付流程，但关键取舍主要依赖上级拍板。 | 只说积极沟通、推动落地，无法说明冲突和处理结果。 |

## 追问句式库

### 要细节

1. “把这一步展开：输入是什么、谁处理、输出给谁、失败时走哪条路？”
2. “请说一个真实样本，按发现、判断、动作、结果复盘。”
3. “你本人具体做了哪一部分？哪些由算法、研发或业务同事完成？”

### 要数字

1. “这个指标的基线、目标、最终值、样本量和统计周期分别是多少？”
2. “成本按调用量、Token、模型单价和人工复核拆开后，各是多少？”
3. “原流程耗时多少、新流程多少，统计口径由谁确认？”

### 要反例

1. “说一个这套方案不适用或明确失败的场景，你当时怎么处理？”
2. “有没有数据与预期相反，迫使你改路线或停止功能的例子？”
3. “如果去掉你认为最关键的能力，结果会怎样？有什么证据？”

### 要决策依据

1. “当时还有哪些备选方案？用哪几个标准排除它们？”
2. “谁不同意你的方案？你拿了什么证据，最终按什么规则决策？”
3. “如果预算减半、准确率下降或合规要求提高，你先改哪一项，为什么？”

## 追问顺序

每道题按候选人回答动态选择 2-3 层：

1. **事实层：** 项目、角色、用户、流程和动作是什么。
2. **证据层：** 数字、样本、基线、统计周期和数据口径是什么。
3. **判断层：** 备选方案、取舍标准、反例、失败边界和复盘是什么。

候选人已主动提供某层证据时跳过重复追问，转向缺失层。

## 止损与换题

1. 取得“具体案例 + 关键数字/样本 + 取舍依据 + 结果/复盘”即视为问透，停止重复追问。
2. 连续 3 轮追问没有新增可验证信息，记录缺口并换维度；不代答、不提示标准答案。
3. 候选人承认没做过时，允许一次假设题验证思考过程，但标记“无项目证据”。
4. 剩余时间不足时，优先保留 JD 硬门槛、简历核心声明、AI技术选型与架构、评测与Bad Case闭环；受监管岗位同时保留安全合规与可靠性。

## 每题输出模板

1. **题干：** 针对简历或 JD 的具体问题。
2. **优先级：** 必问、应问或备用；必问题必须对应本轮招聘假设或 JD 硬门槛。
3. **要验证的招聘判断：** 写明证据成立或不成立会怎样影响本轮决定。
4. **考察维度与二级点：** 一个主维度、一个主二级点；必要时标辅助维度。
5. **追问链 2-3 层：** 覆盖缺失的事实、证据和判断。
6. **判断信号：** 分别写强证据、基本满足、风险信号时能观察到什么，不写标准答案。
7. **这题为什么问这个候选人：** 指向简历、JD、上轮缺口或行业修正的具体文本，不写泛化理由。

## 面试出题模式结尾

1. 检查本轮核心题总数是否符合面试阶段题量。
2. 列出每个招聘假设对应的问题，任一假设没有问题时补题或删除该假设。
3. 检查 JD 硬门槛、简历强声明、岗位原型和行业修正是否至少各有对应问题。
4. 只列待验证项，不输出推进、推荐或录用结论。

## 面试复盘决策

1. 每个已考维度落为“好 / 及格 / 不合格 / 未考”，附一条行为证据。
2. 先判断 JD 硬门槛，再判断画像匹配，不能用总分掩盖硬门槛缺失。
3. 输出“推进 / 有条件推进 / 不推进”，列 3 条最强证据、2 条主要风险和待核验项。
4. 同时输出置信度：高 / 中 / 低。高置信度要求本轮硬门槛均已取得直接证据；存在关键未问到项时不得标高。
5. “有条件推进”必须写明下一轮需要补什么证据，以及证据成立和不成立分别如何改变决定。
6. “不推进”必须由 JD 硬门槛未满足、已证实的高风险错误或岗位级别明显不匹配支持，不能只依据表达风格或总体感觉。
7. 面试官有分歧时回到证据与 JD 权重，不用总分平均或印象投票替代判据。

## 跨轮交接模板

1. **已验证：** 最多 5 项，记录招聘假设和直接证据，下一轮不重复提问。
2. **待验证：** 最多 3 项，区分未问到与问到但缺证据。
3. **矛盾/风险：** 最多 3 项，写明冲突来源和岗位影响。
4. **下一轮问题：** 最多 3 题，只服务待验证或矛盾项，不提供答题提示。
