# Comet 后台任务调度

仅当用户在 build 联合决策中选择 `subagent-driven-development` 且当前平台确实能后台派发时使用。协调者保留计划、OpenSpec 与进度记录，不自行写实现代码；每个实现任务给一个有明确文件归属的 implementer。派发前按 `start-gate.md` 检查当前规格、规则、预算和计划矛盾。子代理接收必要的单任务上下文、项目规则、受影响检查与剩余预算，不携带全量历史对话。

每个 implementer 回报状态 `DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT`、变更文件、提交、实际测试命令与结果、未解决问题。协调者核对工作树可见性与任务文本后勾选 tasks.md；随后自动派发下一任务，直到预算到期、规则或规格漂移、真正阻塞或所有任务完成。

`review_mode: standard` 时不派发每任务 reviewer。所有任务结束后，对当前完整 diff 审查一次；Bundle 启用时由 overlay review 节点执行，协调者不重复审查。`review_mode: thorough` 也不做逐任务审查，完整 diff 一审后由独立审查者做第二审。`review_mode: off` 只适用于未启用 Bundle 且用户明确选择跳过自动审查的流程；仍须执行批准的检查。

审查发现问题时先核实并报告；仅在已批准预算内派发一轮定向修复和受影响复测。同一失败重复、无实质进展或第一轮返工后仍失败时停止。保存当前任务、代码与规格摘要、命令结果、审查发现、返工计数和下一步，交还用户确认新的预算。

测试默认只跑受改动影响的批准命令，单条 10 分钟。相同代码、规格和命令的通过证据复用。项目 AGENTS.md 要求完整回归时照做或先请用户调整；任何子代理都不能自行跳过项目规则。范围、验收场景或适用规则实质变化时先暂停，更新 OpenSpec 并重新确认当前版本。
