# Workflow

Follow this process when building or improving CHL's personal showcase page.

## 1. Build the First Visible Version

- Read the source Markdown documents under `G:\vibecoding\我的AI作品包`.
- Extract the personal positioning, target audience, project story, proof points, and required modules.
- Create a static HTML page in the user-specified output directory.
- Use the fixed avatar path: `G:\vibecoding\我的AI作品包\Image 214.png`.
- Keep the first version simple enough to inspect and iterate.

## 2. Iterate From Feedback

Use CHL's feedback as concrete change requests, especially:

- Content feedback: enrich personal introduction, experience, Agent design ability, methodology, and commercial results only from provided material.
- Visual feedback: fix avatar placement, adjust layout, colors, buttons, spacing, and reference-image style while avoiding dominant purple gradients.
- Direction feedback: make Agent workflow meaningful, not just animated arrows or decorative effects.
- Bug feedback: investigate white screen, garbled text, broken paths, missing images, and layout issues from root cause.

## 3. Required Agent Workflow Content

When showing an energy Agent workflow, explain a real chain such as:

- Site data collection
- System ingestion or data integration
- Agent understanding, analysis, or retrieval
- Task collaboration or exception handling
- Result feedback and business loop closure

Use dynamic effects only to support this chain. Do not let animation replace explanation.

## 4. Presentation Script

Create a Markdown script in `G:\vibecoding\作品讲述稿归档`.

The script should be suitable for a 2-3 minute explanation to interviewers, colleagues, or friends. It should clearly cover:

- What CHL made
- What materials were prepared
- How the first version was generated
- How feedback and iteration happened
- Who can view it now
- What capability the work proves

Use a natural, excited demonstration tone. Avoid stiff AI-style phrasing such as repeated "不是……而是……" structures.

## 5. Verification

After generating or editing files:

- Read back the HTML and Markdown files.
- Confirm the required modules exist.
- Confirm the avatar path is used.
- Confirm the presentation script exists in the fixed archive directory.
- Check for garbled Chinese text, placeholder content, broken local image paths, and obvious missing sections.
