# 第二阶段 竞品分析

## 阶段目标

第二周的重点是把“功能表和截图”升级为 AI 产品架构研究。判断学员是否用公开资料、真实试用和统一测试任务完成了可追溯的横纵分析，能否同时用 ICTSOEVMG Harness 九要素和用户体验五层解释竞品，并把结论转成自己产品的节点、边界和 P0 取舍。

全程区分：**公开事实、实际观察、合理推测、本人决策**。无法确认的内部机制只能写推测、依据和置信度。

## 产品方向框架的用法

使用 `product-directions.md` 延续或校正项目方向，以命中拼图组织竞品的统一任务测试和能力边界观察。可以比较覆盖部分同类能力的竞品，不要求其产品组合完全相同。框架是观察与测试清单，不是竞品内部架构事实；未披露、未测试写未知，不判缺失。

两种产物均在阶段预判中给方向与依据，核心产物用一行列参考组合；将最多 3 项关键拼图发现合入双框架表，连接试用证据、Harness、体验层和自己产品的采用/暂缓/不做决策。无测试证据时给待验证问题和测试动作，不输出虚构的产品取舍依据。

## 结论口径

| 结论 | 触发条件 |
| --- | --- |
| **推进** | 决策问题明确；竞品选择合理；纵向演进与横向测试证据可查；Workflow 反推有依据；已形成自己的节点取舍、P0 与 PRD 重点 |
| **收束** | 已有真实观察，但竞品过多、维度过散、测试不统一，或结论尚未改变自己的设计 |
| **换题或重做** | 只有 AI 摘要或功能截图；没有来源与试用；把猜测写成内部事实；分析后仍说不清自己的系统怎么改 |

## 分环节主持重点

### 对齐决策问题与证据链

- **导师判断**：分析是否服务于产品决策；学员是否把 AI 摘要当研究证据。
- **导师讲解**：竞品研究的最小链路是“问题 -> 来源/试用 -> 观察 -> 推测 -> 自己的决策”。
- **未通过处理**：没有决策问题则先收束；没有来源和试用则不进入机制反推。

### 纵向与横向分析

- **导师判断**：纵向是否解释技术与产品路线变化；横向是否采用统一测试并覆盖失败行为。
- **导师讲解**：重点讲模型能力、Context、Tool、人审、成本和产品形态之间的关系，不替学员判断具体行业路线。
- **未通过处理**：对比口径不一致时，当场固定测试任务和记录模板，旧结论降级为待验证。

### Harness 与四闭环解构

- **导师判断**：可观察证据与内部机制推测是否分开；是否用一次成功演示推断系统完整。
- **导师讲解**：九层 Harness 是黑盒观察坐标，不是要求猜出竞品内部架构；四闭环要从失败、接管、恢复和回归检查。
- **未通过处理**：不可见机制写“未知”；没有失败测试则不能判断闭环完整。

### 产品取舍与收尾

- **导师判断**：研究是否真正改变自己的 Workflow、边界、P0 和方案选择。
- **导师讲解**：差异化优先从数据、工作流、交互、评测和治理寻找，不默认追求更复杂模型或 Agent。
- **未通过处理**：分析未形成决策时，不进入 PRD；会后只补 1-3 个阻断决策所需测试。

## 横纵分析法

### 纵向分析（Diachronic / Longitudinal）

沿时间轴，完整还原研究对象从诞生到现在的发展全貌：

1. 起源背景：技术、模型、数据、产品能力和需求变化；团队、融资或行业环境仅在会改变 AI 产品决策时检查。
2. 首次发布或成立：时间、最初形态与定位。
3. 演进历程：优先看版本、模型/数据能力、架构、交互、工具、人审、评测和治理变化；其他商业事件只保留与这些变化有因果关系的节点。
4. 决策逻辑：每个关键节点为何选 A 而不是 B，当时有哪些约束。
5. 叙事要求：呈现因果关系与时代脉络，不写成干巴巴的年表。

### 横向分析（Synchronic / Cross-sectional）

以当前时间点为切面，将研究对象与同赛道竞品或同类进行全面对比。先判断：

- **无直接竞品**：分析没有竞品的原因、间接替代方案、上一代方案和潜在进入者。
- **少量竞品（1-2 个）**：逐一深入比较。
- **竞品充分（3 个及以上）**：选 3-5 个最有代表性的对象，说明各自路线与生态位。

优先比较 AI 技术路线、Context、工具、交互、评测、人审、安全、时延、成本和可观察边界。商业模式、定价、资源、口碑和生态位只在会影响部署方式、数据路径、成本或风险时检查。观点必须先有事实；推测需明确标注。

### Deep Research 用法

1. 在原始横纵分析 Prompt 中只替换 `研究对象 = 「…」`。
2. 保留纵向、横向、横纵交汇、来源和不确定性要求。
3. 运行后逐条核验来源、时间和版本，不把模型输出直接当事实。
4. 用实际试用和统一测试补足可观察行为；Deep Research 不能替代产品体验。
5. 最后写横纵交汇：历史为何形成当前格局，以及这对自己产品意味着什么。

## 可选追问

追问聚焦 AI 产品研究方法和机制判断；行业信息只要求学员提供来源，不由导师补充结论。

### 1. 目标与证据边界

- “这轮分析要替你回答哪 1-3 个产品决策问题？”
- “哪些来自公开资料、实际试用、合理推测和本人决策？”
- “关键结论的来源、时间与产品版本是什么？”
- “哪条新证据真正改变了原判断？”

### 2. 竞品选择与 AI 路线

- “属于无直接竞品、少量竞品还是竞品充分？”
- “为何选择这些代表性对象，它们各代表什么 AI 产品或技术路线？”
- “测试任务、输入输出或使用边界不同的产品，是否被硬放在一起比较？”
- “没有直接竞品时，上一代与间接替代方案是什么？”

### 3. 纵向演进与技术约束

- “哪些模型、数据、基础设施或产品能力变化推动了它的演进？”
- “从首次发布到现在有哪些关键转折？”
- “为什么当时选 A 而不是 B，约束是什么？”
- “演进如何解释今天的优势、短板和风险？”

### 4. 横向统一测试

- “所有产品是否使用同一任务、输入、语言和相近环境？”
- “测试是否覆盖正常、模糊、冲突、超范围与高风险样本？”
- “产品是否会澄清、引用、承认不知道、拒绝、降级或转人工？”
- “重复运行后，输出稳定性与结构化结果如何？”

### 5. Workflow 与九层 Harness

- “从一次真实测试，能反推哪些输入、路由、检索、工具、校验和输出？”
- “九层中哪些有可观察证据，哪些只能推测或仍未知？”
- “哪个反推节点置信度最低，如何验证？”
- “哪些机制值得借鉴，哪些不适合自己的约束？”

### 6. 四个闭环

- “任务闭环在哪一步断开？”
- “上下文选择、压缩、保存、人工接管和恢复哪些可见？”
- “工具参数、执行、异常、降级与日志有何证据？”
- “反馈是否真正进入失败分类、回归和系统更新？”

### 7. 安全、性能与成本

- “什么输入触发拒答、降级、二次确认或人工复核？”
- “高风险结论是否给来源、置信度、修改入口和最终责任人？”
- “时延、上下文、调用次数和重试如何影响体验？”
- “单次任务的模型、工具与人工成本大致如何？”

### 8. 取舍与 P0

- “分析后，自己的节点、顺序、人工边界和不做项改了什么？”
- “差异化来自数据、工作流、交互、评测、治理还是商业模式？”
- “哪些能力选择 Build、Buy、Integrate 或 Manual，为什么？”
- “三周只验证一条链时，P0 保留什么？”

### 9. AI 协作与本人判断

- “检索、试用、归纳、推测和决策分别由谁完成？”
- “AI 生成了哪些内部机制判断，如何核验或降级为假设？”
- “给一个你拒绝 AI 建议的例子。”
- “能否现场复现一条测试并解释它为何改变了 P0？”

## 双框架对比方法

### 技术层：ICTSOEVMG Harness

使用以下九层原名建立表格，每格写“可观察证据 / 合理推测 / 置信度 / 自己的取舍”，无法观察时写“未知”：

1. Interaction 交互
2. Context 上下文
3. Tool 工具
4. State / Memory 状态记忆
5. Orchestration 编排
6. Execution 执行沙箱
7. Verification 验证
8. Monitoring 可观测
9. Governance 治理

### 产品层：用户体验五层

每个竞品只记录影响产品决策的证据、未知项和启示：

1. **战略层**：目标用户、核心任务、AI 价值和成功指标。
2. **范围层**：P0 能力、非目标，以及 AI、规则、工具、人工的边界。
3. **结构层**：任务流程、信息架构、分支、失败恢复和人工接管。
4. **框架层**：界面、导航、状态反馈、澄清、引用、确认和修改入口。
5. **表现层**：视觉与文案怎样表达置信度、来源、风险和下一步动作。

输出时不要分别写两篇长分析。使用一张双框架关键发现表：`证据 -> Harness 判断 -> 体验层判断 -> 对自己产品的取舍 -> 待验证项`。

检查四条闭环，链路文字和顺序不得改写：

- 任务闭环：`识别 -> 查询 -> 检索 -> 审核 -> 初稿 -> 发送`
- 上下文闭环：`选择 -> 压缩 -> 保存 -> 人工接管 -> 恢复`
- 工具闭环：`选择 -> 参数校验 -> 执行 -> 异常处理`
- 评估闭环：`标准答案 -> 指标阈值 -> 离线测试 -> 失败分类 -> 回归集 -> Prompt/RAG/Harness更新`

不能用一次成功演示推断闭环完整。逐条检查验收、失败回跳、人工接管、恢复、权限、日志和回归证据。

## 默认产物：导师主持提纲

使用通用方法论的默认顺序，并针对第二阶段填充：

1. **会议目标**：最多 3 条，确认研究可信度、双框架判断和产品取舍。
2. **阶段与预判**：一句话给阶段判据、已有证据、最大缺口和预判。
3. **60 分钟会议执行表**：只使用本文件的五个时间盒；主持提示和知识讲解合并在表内。
4. **双框架关键发现表**：最多 3 条，只列影响自己产品节点、边界、P0 或验证计划的发现；不逐项复述九要素、五层或四个闭环。没有统一测试证据时，只写当前不能判断什么及需要补哪项测试。
5. **当场结论与会后任务**：阶段结论、设计变化、最多 3 项补测任务、验收证据和进入第三阶段条件。

不要默认输出完整竞品点评报告；把已有判断放进对应会议环节，帮助导师讲清研究方法和 AI 产品取舍。

## 显式产物：评估报告骨架

仅当用户明确要求书面评估报告时，按以下顺序输出：

1. **结论**：推进 / 收束 / 换题或重做；一句话判据与关键证据。
2. **已扎实部分**：决策问题、纵向证据、横向测试证据与已形成的取舍。
3. **完整性检查**：研究对象与竞品选择、纵向、横向、统一测试、事实/推测分离、节点决策；每项列证据、缺口与判断。
4. **关键问题与修改建议**：只列 1-3 个最大缺口；每项写证据、重要性、修改动作与验收证据。
5. **Workflow 与 AI 能力反推**：可观察行为、合理推测、依据、置信度、未知项及对自己的影响。
6. **九层 Harness 对比**：九层逐项写竞品证据、推测与自己的取舍。
7. **四个闭环**：逐条写可见链路、断点与证据状态。
8. **认知偏误**：偏误、作业表现、点破与修正。
9. **Now / Next / Later**：Now 只放阻断进入 PRD 的事项。
10. **当面追问**：问题及合格回答应包含的证据。
11. **AI PM 结论**：已证明什么、尚不能证明什么、进入第三阶段的条件。

## 阶段交付门槛

- 分析明确回答 1-3 个产品决策问题。
- 竞品选择有路线和生态位理由。
- 纵向包含起源、发布、演进、转折与决策逻辑。
- 横向采用统一测试任务，覆盖正常、边界、冲突、超范围和人工确认。
- 事实带来源与时间；观察、推测、未知和决策明确分开。
- 实际试用保留输入、输出、版本、时间和失败记录。
- 九层 Harness 未知项没有被虚构填满。
- 四个闭环已标出断点。
